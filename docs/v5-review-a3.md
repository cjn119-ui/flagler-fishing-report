## Checks that matched the approved decisions

- Regional shrinkage matches the ADR formula and worked arithmetic. January is tested with its December and February neighbors; add a December query to cover the Dec/Jan wrap in the other direction.
- The season factor is the species-relative monthly rate divided by that species' peak. Prevalence is not used as a factor score. The `<0.10` relative-season and outside-water caps are applied at 20; non-realistic eligibility prevents GO without adding an absolute-rate suitability cap.
- Missing factors are listed and excluded from the normalized available-weight sum, as specified. With an unavailable tide factor, the current code subtracts 20 confidence points and emits `tideUnavailable`; the test's weaker assertion could be tightened to assert the exact value. This renormalization is explicit in the factor row and confidence reason, not an unreported scoring path.
- Trapezoid ramps/plateau, wind bearing wrap (facing 350°, wind-from 10°), Moderate-confidence GO, structural-reason qualifier exemption, safety gates, tomorrow wave coverage, and fall-back DST slot generation passed their existing cases.
- Tie logic uses an inclusive five-point comparison and checks `targetDate`; add exact-five-point, preference-key-change, and same-date scope/focus tests.
- The scoring path contains no `Date.now()` or hidden network request. `loadFirstCoastHistory` has an explicit `fetch` fallback for loading the static artifact and an injectable `readJson` seam. Node importability is exercised by the model test under Node 26.8.1; a browser import smoke was not run.

## Coverage assessment and A5 requirements

[`coverage-v5.mjs:31`](/Users/christiannunez/flagler-fishing-report/scripts/coverage-v5.mjs:31) builds one instant with `calculateFactors`; [`coverage-v5.mjs:33`](/Users/christiannunez/flagler-fishing-report/scripts/coverage-v5.mjs:33) calls `verdictFor` directly with `conditionsReady:true`. This is a useful **factor-level synthetic screen**, and its header correctly says “candidate only.” It is not a fair end-to-end reachability test for a recommendation: it does not call `scoreSpecies` or construct a 60–150 minute window, and it bypasses model caps. For example, a relative season score of `.05` with otherwise ideal factors can have raw fit above 70 in this script and report GO, while `scoreSpecies` applies the approved out-of-season cap of 20. A lone 30-minute input cannot produce the required recommendation window.

### Luna High fix list for A5

1. Fix the seven findings above. Keep the season-timing and missing-factor rules from Revision 2 intact.
2. Add regression cases for lunar date boundaries/underfoot periods, raw-score window aggregation at the GO threshold, partial history with an independently available current month, slack tide, every eligibility value including bycatch driver rejection, and parameterized slot duration.
3. Retain the current script as a clearly labelled factor-level screen, then add an end-to-end coverage check using `scoreSpecies` with contiguous 30-minute inputs. Require a real 60–150 minute window, the model's caps, eligibility, confidence, forecast/alert/wave gates, and final verdict; report all active location × mode × month denominators.
4. Keep synthetic reachability separate from observed-data frequency. The ADR launch gate still requires the full-year real-observation hindcast and its source-completeness denominators; this script cannot substitute for it.
5. Add direct boundary tests for the five-point tie and same-date hysteresis with changed favorites/preferences, plus an actual browser module-import check and deterministic fixed-input comparison.

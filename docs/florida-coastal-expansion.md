# Florida coastal expansion

Status: local implementation built (2026-10-18); simulator interaction and product acceptance remain pending.

## Product scope

- Expand from the St. Augustine–Flagler catalog to Florida coastal saltwater.
- Let an angler choose a coastal point on the map instead of requiring a cataloged spot.
- Keep the existing surf, pier, and inshore modes. The angler must choose a mode when a point does not identify one.
- Preserve the existing Flagler/First Coast experience and its saved reports while the new path is built.
- Inland freshwater fishing is out of scope for this expansion.

## Current constraints

- `site/v5/proto` reads precomputed `/api/v5/today.json` and `tomorrow.json`; those runs only include `ACTIVE_SPOTS`.
- `site/v5/engine/sources.js` can fetch several inputs from coordinates, but tide, buoy, CDIP, water-temperature, and access context are still supplied per catalog location.
- `site/v5/engine/history.js` reads the existing `first-coast-history.json` for precomputed runs. A separate statewide Florida shore-survey artifact now exists for user-selected points.
- A point-specific forecast uses the same on-device engine and resolves a nearby NOAA CO-OPS tide station. Coordinate weather and marine forecasts are fetched for the chosen point; the First Coast marine snapshot is explicitly excluded from this path.
- The live NWS forecast API accepts coordinates and discovers the applicable grid point. NOAA CO-OPS exposes station metadata with coordinates and prediction-station type. NOAA MRIP publishes Florida public-use survey data and calibrated estimates. These are candidates for the new providers; coverage, station-distance limits, and current schemas still need implementation checks.

## Implementation sequence

1. **Implemented locally:** MapKit starts at a Florida-wide extent and long-presses a point into a Surf / Pier / Inshore chooser. The point is retained on device.
2. **Implemented locally:** Florida CO-OPS tide metadata is bundled; a point more than 35 miles from its nearest prediction station is rejected. The nearest station name and distance are shown. NWS/Open-Meteo/marine forecasts use the selected coordinates; the First Coast NDBC snapshot is not used.
3. **Implemented locally:** `florida-coastal-history.json` contains separate 2015–2025 East Atlantic, Gulf Coast, and South Atlantic & Keys shore-intercept MRIP groups. Surf/pier use ocean stratum; inshore uses estuarine/inland stratum. The South Atlantic & Keys point region is selected south of 25.8°N; otherwise longitude -81.7° separates Gulf from East Atlantic. These broad survey regions are not point-level estimates.
4. **Implemented locally:** today/tomorrow runs are generated by the existing engine and cached locally, without changing the scheduled First Coast generator.
5. Capacitor bundle rebuild and native simulator-target compile succeeded. Pending: visually verify a Florida point selection in a booted iOS Simulator. Confirm time-zone boundary and nearest-station behavior independently before product acceptance.

## Current source limitations

- The point path does not yet resolve a coast-wide NDBC/SECOORA buoy catalog or nearest observed water-temperature sensor. Fresh coordinate-based wave forecasts are available where the provider covers the point; current buoy and water-temperature observations may be unavailable. Existing confidence and missing-data caps remain in force.
- Florida MRIP context is county-aggregated to broad coast regions, not a local point estimate. The app labels the selected region and must not describe the survey rates as point-level catch odds. The cached 2015–2025 sample contains no ocean-stratum shore interviews in the Gulf group and no Monroe County interviews; Gulf surf/pier rates therefore stay unavailable, while South Atlantic counties provide explicitly disclosed adjacent context for Keys points.

## Acceptance boundary

- A user can select any supported Florida coastal coordinate, choose surf/pier/inshore, and receive a locally cached point-specific outlook.
- Each live input identifies its source, station, distance where relevant, age, and fallback state.
- The app never labels a First Coast survey rate as statewide or implies suitability is catch probability.
- Existing Flagler runs and the legacy root app continue to work.
- This is local implementation only. No deployment, publish, external account change, commit, or push is included.
